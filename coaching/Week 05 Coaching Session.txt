User: /**
 * Middleware factory to require specific role for route access
 * Returns middleware that checks if user has the required role
 * 
 * @param {string} role - The role name required (e.g., 'admin', 'user')
 * @returns {Function} Express middleware function
 */
const requireRole = (role) => {
    return (req, res, next) => {
        // Check if user is logged in first
        if (!req.session || !req.session.user) {
            req.flash('error', 'You must be logged in to access this page.');
            return res.redirect('/login');
        }

        // Check if user's role matches the required role
        if (req.session.user.role_name !== role) {
            req.flash('error', 'You do not have permission to access this page.');
            return res.redirect('/');
        }

        // User has required role, continue
        next();
    };
};.... this function factory works by taking the role that we want to requiere as a parameter, which is later passed into the function that comes from this factory, which is a middleware functions that is usually called before any other middleware function and makes sure the user has the requiered role before procceding with the rest of the middlewares and/or rendering the page.  this ensures that certain routes are protected and certain are public

Assistant: Excellent, Yain — you’ve explained the middleware factory pattern very clearly. By returning a function with the `(req, res, next)` signature, Express can plug it directly into the routing chain, and you avoid duplicating code for each role. That’s exactly the kind of pre‑configuration function factories are meant for.
