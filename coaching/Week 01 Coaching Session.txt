👉 Now, sticking to our single-question coaching style: why did you choose to use res.render() here instead of res.send() or res.json()? What specific advantage does render give you in this project?

Yes, you’ve got the right idea. res.render() is specifically designed to work with template engines like EJS, so it takes your template file (like home.ejs), injects the variables you pass ({ title }), and then produces the final HTML that gets sent to the browser.

res.json() sends JSON data, which is useful for APIs but not for rendering a page.

So your instinct is correct: render is the one that ties Express to EJS and lets you build dynamic pages.

👉 Next, let’s move into Topic 2: JavaScript language principles. Could you paste a snippet of a JavaScript function you wrote (not trivial, something with a bit of logic), and then explain what principle or concept of JavaScript you were applying when you wrote it?

export default function VisitDisplay() {
    const welcomeMsg = document.querySelector(".welcome-msg");
    const dateNow = Date.now();
    const lastVisit = localStorage.getItem("last-visit-ts")
    const msToDays = 86400000;
    let daysDifference = (dateNow - lastVisit) / msToDays;
    let daysText = "day";

    if (lastVisit == null) {
        welcomeMsg.textContent = "Welcome! Let us know if you have any questions.";
        localStorage.setItem("last-visit-ts", dateNow)
    }

    else if (daysDifference < 1) {
        welcomeMsg.textContent = "Back so soon! Awesome!";
        localStorage.setItem("last-visit-ts", dateNow)
    }

    else {
        if (daysDifference >= 2) {
            daysText = "days"
        }
        welcomeMsg.textContent = `You last visited ${daysDifference.toFixed(0)} ${daysText} ago`;
        localStorage.setItem("last-visit-ts", dateNow)
    }
} .... When I wrote this JS Function, I applied the principle of LocalStorage, Modules, DOM Querry Selection, and simple mathematical logic (e.g.: if X is greater than Y then....)
That’s a solid breakdown—you’re clearly applying multiple JavaScript principles in one function: localStorage persistence, DOM manipulation, modular exports, and conditional logic. You’re also handling time math with Date.now() and converting milliseconds to days, which shows good practical reasoning.

👉 To deepen your understanding: why did you choose to store the timestamp (last-visit-ts) in localStorage instead of, say, storing just the number of days since last visit? What advantage does keeping the raw timestamp give you?

I am not 100% sure of the advantages, but i would say that it allows for flexibility If in the future I choose to also keep track of the date and for example, display it with a message like "Your last visit was (DATE)"
Exactly—that’s a smart intuition. By storing the raw timestamp, you keep the full flexibility of the data. You can later calculate not just “days since last visit” but also show the exact date/time of the last visit, or even track patterns over multiple visits. If you only stored the number of days, you’d lose precision and be locked into that one calculation.
